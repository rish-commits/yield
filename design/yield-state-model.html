Yield · behaviour spec

State Model.

Every state the panel can be in, every transition, and — the part that matters — what happens when the agent's timeline and the user's timeline collide. Built to have no loose ends before any of it gets skinned.

Core principle

The user's input timeline is independent of the agent's timeline. A person can add context any time — idle, mid-task, between tasks. The agent starting or finishing never interrupts, discards, or rushes what the user is doing. Agent state changes only the ambient feel of the panel; it never gates the ability to contribute. Everything the user saves lands in context.md regardless of what the agent is doing.

01 The two timelines

Two independent clocks. The agent's is driven entirely by Claude Code hooks. The user's is driven entirely by the person. They run in parallel and occasionally cross — those crossings are Section 04.

05 Which task does a note attach to?

Every note is paired with a "task" for legibility in context.md. Because the timelines are independent, we need one clear rule for the pairing — otherwise a note written across a task boundary is ambiguous.

Rule: a note is tagged with the task that was active when the user started composing — because that's the context they were reacting to. If nothing was running when they started, it's tagged general and attaches to the next task (or saves as standing context if none comes). The tag is set at compose-start, not at save-time, so a task ending mid-compose doesn't re-point the note.

This is a decision, not a law of physics — it's the "you're reacting to what you saw" model. Flagged here so it's explicit and reversible, not silently baked in.

06 Edge cases & empties

Rare, but real. Each has a rule so nothing silently breaks or nags.

CaseRule
Very short task (<~400ms)Debounce the "alive" transition. If Stop arrives before the debounce, skip the alive animation entirely — no jarring flash for a 2-second task.
Very long task (>~30s)Settle the ambient from lively to a calm "still working" so a long run doesn't fatigue the eye.
Rapid successive tasksRe-trigger "alive" cleanly on each UserPromptSubmit; never stack or double-animate.
Empty save attemptEnter with an empty field is a no-op. Nothing written, no error.
First run everOnboarding state — a one-time "here's what Yield is / what to do." Deferred to its own phase, but the slot exists in the model.
No history yetThe recent-note line shows a gentle empty state — an invitation, not a blank: "Nothing yet — add something for next time."
Listener downPanel shows a quiet, non-blocking status: it can't hear the agent right now. Input still works and still saves to context.md.
Transcription failsKeep the audio/last text, show an inline retry. Never lose what was spoken. Error explains what happened, in the interface's voice.
Write to context.md failsHold the draft in the panel, surface an inline error with a retry. The note is never silently dropped.

08 What drives what

The one separation that keeps the whole model clean:

Agent state drives only the ambient display — whether the panel feels resting or alive. It has zero authority over input.
User state drives the input flow — composing, saving, confirming. It runs on its own clock and is never preempted by the agent.

Because these two never gate each other, every collision in Section 04 resolves the same way: the agent changes the mood, the user keeps control. No loose ends.
