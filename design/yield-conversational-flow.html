Yield · conversational flow

Scripted Flow. v1 blueprint

Turns the input from a blank box into a two-way exchange: Yield asks, the user answers or free-types, Yield acknowledges and saves. Scripted for v1 (instant, reliable); built so an LLM can replace the script later without changing the UI.

Core principle

Bidirectional, never a gate. Yield offers a question; the user can answer it, skip it, or ignore it and free-type. The free-type box is always live. Yield reacts to what it gets (a short acknowledgment) so the exchange feels alive, but it never blocks input, never nags, and stays silent when it has nothing worth asking.

02 The two states

StateBehavior
First-timeBrief intro (one line: what Yield is), then eases into the first question. Higher guidance. This is the onboarding moment.
ReturningNo intro. Straight to a question (contextual if the current task matches, else a single soft opener, else silent).

03 The core loop

1
Trigger. A task starts (or panel opens). Yield checks the current prompt for a keyword match.
2
Ask. Match → contextual question. No match → one soft general opener (returning) or intro+opener (first-time). Nothing good to ask → stay silent, show input only.
3
User responds. Answers the question, taps skip, or free-types something else. All three are valid.
4
Acknowledge + save. Yield gives a short reply, writes the note to yield-context.md, bumps the note count.
5
Continue or rest. At most one gentle follow-up if the user engaged. Then Yield backs off to the resting input. Never a barrage.

04 Question & acknowledgment scripts

Keyword in the current prompt → Yield's question → short acknowledgment after the user answers. Kept as data so an LLM can later generate these instead. Acknowledgments rotate so they don't feel canned.

05 First-time intro copy

Hey — I'm Yield. While your agent works, tell me anything it should know and I'll remember it for every run.
To start: anything it should keep in mind on this project?
use pnpm, and don't touch the /legacy folder
Noted. That's saved — I'll bring it into future runs.

Intro is one short self-introduction, then straight into the first question. Shown once, ever. After the first answer, the user is "returning" from then on.

06 The four safety behaviors

Nothing relevant to ask → Yield stays silent and shows only the resting input. It never invents a filler question. Silence is a feature.
User skips / ignores → if the last 2–3 questions were skipped or ignored, Yield stops offering questions for this session and just shows the input. It reads the room.
User free-types instead of answering → the typed note is accepted and saved normally, with a neutral acknowledgment. Yield does not repeat or re-ask its question, and doesn't act like the user "missed" it.
Interrupted mid-answer (task ends) → the draft is preserved (per the state model). The exchange pauses, nothing is lost, the note simply targets the next run.

07 Volume & tone rules

One question per wait by default. One gentle follow-up only if the user actively answered. Never a chain of 3+.
Tone: calm, warm, brief. Acknowledgments are 3–8 words. No peppy chatbot energy, no emoji spam, no exclamation overload. It sounds like a thoughtful colleague, not a mascot.
Yield speaks only when useful. A quiet panel is better than a chatty one. The goal is a helpful nudge, not a conversation partner that won't stop.

08 Built for the LLM upgrade

Future pipeline — do not lose
  • 2a — LLM replies: swap the scripted question/ack lookup for a free/local model (Gemini Flash, Groq, OpenRouter) or the Claude Code agent itself. Not paid. Blocker is latency — layer it so it falls back to scripts when slow.
  • 2b — File-based project detection: read package.json / lockfiles / configs to detect the real stack — project-aware questions. No AI, no cost, low latency. Likely the next thing after v1.
  • 2c — Deep codebase analysis: summarize a large repo for bespoke questions. The heavy one (big repos, caching, freshness). Later.

Design constraint that makes the upgrade cheap: questions and acknowledgments live in a data structure (trigger → question → ack). The loop and UI read from that structure. Level 2a just replaces "pick from the list" with "ask the model" — no UI or flow rewrite.
